V74.0.13.2 root cause -> corrective action
========================================

Observed V74.0.12 screen at ~00:03:56 before the first startup movie:
- SharpEmu overlay: ~0.2 FPS / ~4942 ms per presented frame.
- Windows Task Manager .NET Host: ~7398.6 MB RAM, ~85.5% GPU, ~73.7% CPU.
- System GPU ~86%, CPU ~82%.
This is an emulation/render bootstrap bottleneck, not a Bink decode bottleneck.

Prior V74.0.11 result:
- peak working set ~11460.3 MB
- peak private memory ~16798.9 MB
- natural ps_studios_logo observed
- once reached, host movie decode completed in about 9.48 s
- 4K 3840x2160 guest target activity was present before/around startup media

V74.0.12 runner defects reproduced by source audit:
- status string used a concatenation / -f layout that PowerShell evaluated such
  that the first placeholders remained literal.
- natural-movie regex used double backslashes in a PowerShell string; PowerShell
  does not treat backslash as an escape character, so the regex was wrong.
- first-completion deadline logic only accepted a candidate deadline when it was
  earlier than the current one; it could never extend a nearly-expired 360 s run.
- final [IO.File]::ReadAllText(stderr.log) did not use sharing/retry and therefore
  threw IOException while the redirect writer/child process retained the handle.

Corrective strategy:
- Release runtime + existing renderer's 0.5 scale for non-storage RT/depth.
- cache ceilings and forced-off ambient diagnostics/overlay.
- retain all guest draw/compute ordering (no blind draw or shader skipping).
- robust one-shot Bink completion header fallback after real playback completes.
- repaired runner milestones/deadlines/process-tree teardown/shared final log read.


V74.0.13.1 packaging regression found on 2026-08-15:
- scripts/precheck.ps1 assigned `$host=...`.
- PowerShell variable names are case-insensitive; `$host` is `$Host`.
- `$Host` is automatic/read-only, so PRECHECK failed before repository checks.
- The same collision was present in apply_build.ps1, run_fastboot.ps1 and inside
  Test-V74013State in common.ps1.
- The runner also assigned `$args`, shadowing automatic `$Args`.

V74.0.13.2 corrective validation:
- no direct assignments to Host/HOME/PWD/PID/PSHOME/ShellId/Input/Args/Error/
  LASTEXITCODE/MyInvocation/PSScriptRoot/PSCommandPath/StackTrace/ExecutionContext/
  PSBoundParameters/PSVersionTable/PSEdition;
- every .ps1 is parsed with System.Management.Automation.Language.Parser;
- every .cmd local target is resolved and existence-checked;
- SHA256 manifest still covers all package payload files.
