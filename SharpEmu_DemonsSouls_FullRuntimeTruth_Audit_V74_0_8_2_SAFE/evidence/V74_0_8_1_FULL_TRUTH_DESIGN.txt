V74.0.8.1 changes diagnostic strategy.

Previous sequence isolated one suspected cache at a time. That was useful for
proving several blockers, but is no longer efficient now that:
- CLR FailFast is fixed;
- compute texture resolver is fixed;
- DCC giant CPU snapshots are suppressed;
- large snapshot churn is greatly reduced;
- sampled GuestImage residency proved small.

The remaining problem can reside in managed GC, Vulkan residency, deferred
retirement, direct/native guest memory, system commit, GPU memory, or
submission back-pressure.

V74.0.8.1 therefore measures all of those in one controlled 120-second run.
No follow-up run should be needed merely to discover which memory domain owns
the missing GiB.
