V74.0.84.1 parser/guard correction

The V74.0.84 package did not modify source because Windows PowerShell rejected scripts/apply_build.ps1 before execution.
Root parser defect:
    $eb.Replace($needle,NL($replacement).Trim("`n"))
PowerShell command invocation cannot be nested there as a normal expression.

V74.0.84.1 changes that to two parser-safe statements:
    $replacementNormalized=NL $replacement
    $replacementNormalized=$replacementNormalized.Trim("`n")
    $eb=$eb.Replace($needle,$replacementNormalized)

Additional hardening:
- all apply/precheck normalization calls use explicit command invocation;
- package validation still invokes System.Management.Automation.Language.Parser on every .ps1;
- validation includes a regression guard against the exact nested-NL parser bug;
- RUN_5 refuses to start SharpEmu unless the V84.1 source markers are actually installed, so a failed APPLY cannot accidentally test an old binary.
