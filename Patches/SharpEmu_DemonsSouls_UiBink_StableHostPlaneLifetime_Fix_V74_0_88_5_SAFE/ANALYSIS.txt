SharpEmu Demon's Souls V74.0.88.5 SAFE

Evidence from V74.0.88.4 runtime:
- Process exit was 0xC0000005.
- main_menu.bk2 was never attached.
- logo_intro_loop.bk2 was not host-rewound, so the V74.0.88.3 main-menu-only loop scope worked as intended.
- The fatal stack ends at Silk.NET.Vulkan.Vk.CmdCopyBufferToImage called by VulkanVideoPresenter.RecordTextureUploads during an offscreen draw.
- Immediately before the fault, the title-loop Bink Y/UV pair is bound and the sticky host-plane path is active.

This moves the root cause away from title-timeline handoff and into the V74.0.88 host-movie plane upload lifetime.

V74.0.88 introduced a new dynamic host VkImage format:
  desiredLumaFormatV74088   = GetTextureFormat(1, guest NumberType)
  desiredChromaFormatV74088 = GetTextureFormat(3, guest NumberType)

It also made the cached host image invalid whenever the observed guest NumberType changed.

Why this is unsafe:
TranslatedDrawResources stores TextureResource.Image handles. A host plane resource can therefore outlive the draw that selected the current guest descriptor contract. If a later draw changes n0/n4 and EnsureHostMovieImages destroys/recreates the host image solely because NumberType changed, already-translated resources can still carry the old VkImage handle. A later RecordTextureUploads then passes that stale native handle to vkCmdCopyBufferToImage.

V74.0.88.5 correction:
- Keep NumberType=4 support for detecting Bluepoint's Y/UV guest descriptors.
- Keep V74.0.88 single-plane bootstrap and V74.0.84.2.1 sticky-plane address learning.
- Decouple host converted YUV storage from guest NumberType.
- Host decoder Y and UV bytes use stable R8Unorm/R8G8Unorm VkImages for the active movie lifetime.
- Guest NumberType no longer invalidates/recreates those host VkImages.
- Add a host-movie upload trace immediately before vkCmdCopyBufferToImage.
- Reject obviously invalid zero buffer/image/extent/layer uploads before the native call.
- Preserve V74.0.88.3 main-menu-only loop scope.
- Preserve V74.0.88 in-window IME.
- Preserve the V74.0.88.4 robust cmd.exe live-log runner.

The purpose of the upload trace is also diagnostic: if another native fault remains, the final lines will show the exact plane, frame serial, staging buffer handle, image handle and copy extent that reached the Vulkan upload path.
