The V74.0.86.1.3 structural Presenter patch succeeded before compilation:
- SOURCE PATCH APPLIED

The build then failed only in ImeDialogExports.cs, beginning around line 395 and cascading to 655 C# errors.

Root cause:
The larger OSK was embedded in a C# verbatim string (var script = @"...").
The PowerShell keyboard definition contained a double-quoted apostrophe key and the script contained other double quotes. In a C# verbatim string, every embedded double quote must be doubled. One raw double quote ended the C# string, so the following PowerShell lines were parsed as C# source.

V74.0.86.1.4 correction:
- The complete WinForms OSK PowerShell script is stored as a UTF-16LE Base64 constant.
- The existing powershell.exe -EncodedCommand path consumes that constant directly.
- No PowerShell source text is embedded inside a C# string anymore.
- RUN_1 now extracts the Base64 payload, decodes it, and parses the embedded PowerShell script with the Windows PowerShell parser.
- RUN_1 also rejects any regression back to `var script = @"`.
- The V74.0.86.1.3 final-return Y/UV learning strategy is preserved as V74.0.86.1.4.
- Build failure still triggers SAFE rollback.
