EBOOT/guest contract findings:
- Demon's Souls contains FrontEndCharacterCreator, CharacterCreator* state/loadout names, equip_player_preview, and CCPLdr character-creator routines. The game owns the Character Creator state and requests a player preview.
- The EBOOT references BinkMovieTextureDataSource/UIBehaviorBinkMovieTextureDataSource, so the UI movie is a texture producer used by guest composition, not a separate fullscreen host window.
- The EBOOT imports libSceImeDialog/libSceIme. The PS keyboard visual is system UI supplied by the console service; it is not the Character Creator's own keyboard mesh/UI asset. SharpEmu therefore needs to emulate that system UI inside its game window.

Renderer finding from the supplied runtime:
- main_menu.bk2 is successfully opened internally by NIHAV.
- Prior Bink miss diagnostics expose likely movie planes as guest format/number-type f1/n4 and f3/n4.
- Existing host-movie candidate code accepted only NumberType=0 and created R8Unorm/R8G8Unorm images.
- NumberType=4 maps to R8Uint/R8G8Uint in SharpEmu's own GetTextureFormat contract.
- Therefore the host replacement was either not selected or had the wrong typed VkFormat for the shader, which matches green/magenta texture interpretation artifacts.
