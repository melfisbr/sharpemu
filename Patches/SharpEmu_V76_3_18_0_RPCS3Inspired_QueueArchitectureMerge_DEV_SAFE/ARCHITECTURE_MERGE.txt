SharpEmu V76.3.18.0 — RPCS3-inspired queue merge

This package does not copy RSX logic. It merges host scheduling principles that
already have native equivalents in the SharpEmu Vulkan backend.

PRESERVED FROM THE CURRENT CHAIN
- V17.0.1 asynchronous AGC command processor.
- V17.1 bounded compute chain 4 with the broad safety barrier unchanged.
- V16.1.1 dependency-driven producer slices.
- V16.0.1 rollback of the failed host-only sideband scheduler.
- V15.1 safe memcpy for PPSA01341.
- queue envelope 192 items / 96 MiB / burst 4 / inflight 16.
- host lanes 6.
- ordered microbatch enabled.
- WAIT_REG_MEM semantics and 16ms producer-less fallback.
- WRITE_DATA / RELEASE_MEM / EOP.
- range hazards, queue-completion fences and presentation ordering.
- Bink/resource strict scope.

NEW MERGE
1. Real second Vulkan queue requested for Demon's Souls.
2. Presenter remains capability driven:
   - selected queue family must support compute;
   - queue count must be >= 2;
   - Vulkan timeline semaphores must be supported.
   If any condition is false, it automatically remains single-queue.
3. DCB graphics stays on queue index 0.
4. ACB compute uses queue index 1 only when dual physical is enabled.
5. Cross-lane waits are driven by the existing resource/range hazard tracker
   and per-lane timeline semaphores.
6. Present joins the compute timeline only when tracked access requires it.
7. Guest command-buffer recycle pool grows from 32 to 256. This is a reusable
   host pool, not 256 Vulkan queues.
8. SHARPEMU_V763180_FORCE_SINGLE=1 is an explicit emergency A/B fallback.

NOT CHANGED IN THIS PHASE
- No separate queue family is selected for transfer. Same-family queue 1 is used
  because this avoids queue-family ownership-transfer hazards.
- WAIT full-scan fallback remains 16ms.
- No host-only sideband reclassification.
- No weakening of compute barriers.
- No forced VRAM allocation.
- No fake wait completion.

WHY
The current log shows the selected Vulkan family exposes 16 queues, compute
support and timeline semaphores, but requested=0 forced all DCB/ACB work through
one VkQueue. The backend already contains the two-queue/timeline/range-hazard
implementation, so the first safe RPCS3-inspired step is to actually use it.
