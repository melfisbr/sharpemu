V74.0.67.2.16.1 - PARAMETER BLOCK ORDER FIX

Observed failure
================
RUN_4 reached source_audit.ps1 and failed under Set-StrictMode:

  A variável '$OutputPath' não pode ser recuperada porque ainda não foi definida.

Root cause
==========
source_audit.ps1 and analyze_runtime.ps1 dot-sourced common.ps1 before their
script-level param(...) block:

  . (Join-Path $PSScriptRoot 'common.ps1')
  param(...)

common.ps1 enables:

  Set-StrictMode -Version Latest

In Windows PowerShell, a script-level param block must be the first executable
statement in the script (comments/blank lines may precede it). Because the
dot-source statement came first, the later param(...) was not functioning as
the script parameter declaration and StrictMode attempted to resolve the
parameter variable before it existed.

Correction
==========
Both parameterized scripts now use:

  param(...)
  . (Join-Path $PSScriptRoot 'common.ps1')

This fixes both:
- RUN_4_DIAGNOSTIC -> source_audit.ps1 -OutputPath ...
- RUN_5_OPEN_GUI -> source_audit.ps1 and analyze_runtime.ps1

Runtime/source behavior
=======================
No emulator runtime source is modified.
No DLSS code is modified.
No RAM TTL/cache behavior is modified.
No wait/scheduler behavior is modified.

V2.15 RAM/frontend state and V2.14 DLSS command-buffer state remain preserved.
